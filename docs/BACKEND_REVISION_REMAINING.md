## Earlier A–D and security audit carryovers

These stay open even if the new numbered schema/API tasks pass:

- **A, live photography path:** owner upload → newly generated watermarked derivative → intentionally selected published staging gallery → anonymous viewing, plus password/private/current access revocation from clean sessions. Current private sample checks do not prove public launch readiness.
- **A, reliability:** representative Worker CPU/memory/decoder limits, disconnect/retry/re-reservation behavior, corrupted/missing R2 recovery, large-library upload UX, bulk/drag ordering, explicit SmugMug/browser-local migration and backups.
- **B, live proof workflow:** saved customer selections/notes visible to owner in another deployed session/device, password-unlock behavior and later revocation; accessibility/keyboard/mobile/offline/error checks; useful share/buy controls only when server contracts exist.
- **B, notifications/delivery:** threaded comments, real notification delivery, authorized customer download controls and whole-gallery fulfillment (not just download-policy copy).
- **C, provider payment acceptance:** local quote→Stripe→ledger→entitlement→R2→refund revocation, duplicate/late/failure/expiry and independent-connection coupon/session/refund contention. Signed unbound sample-event rejection is only a negative test.
- **D, metadata and photographer workflow:** live approved public search with private data exclusion; event/gallery defaults and safe bulk metadata; strongest-first culling; export/provenance metadata; QR event access, scope-limited selected-photo Quick Share and commercial licensing inquiry.
- **Security:** complete dependency audit against an available advisory service; dedicated full-history secret scanning; broader nonce/script CSP design without breaking auth/preview; distributed password abuse monitoring and retention cleanup; review legacy callback/server-function reachability rather than relying on hidden UI.
- **Product/operations:** server-backed studio branding/settings (legacy local Settings remains disabled), explicit cover/alt text editing, bundle/performance measurements and revocation-safe derivative cache policy. Do not alter the approved public style as part of this backend work.
- **Release safety:** required remote GitHub checks, review branch history, exact staging bindings/config, guarded forward migrations and independent production capability gates. Never blindly deploy the unresolved root Wrangler config.

## Intentionally not implementable as promised / out of scope

- Browser screenshot-blackout or guaranteed screenshot/watermark-removal prevention. Continue private originals, controlled access and visible watermarked previews; describe right-click blocking honestly as a deterrent.
- Exact SmugMug parity, unlimited storage, multi-photographer SaaS billing, native mobile/desktop applications, an open page builder, automatic face identification, automatic publication or automatic AI approval.
- Business/legal/tax judgments, real customer consent and owner photo selection cannot be invented by an implementation agent. A technically valid integration is not those decisions.
