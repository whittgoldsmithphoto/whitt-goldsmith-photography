# Backend capability manifest

Contract inventory for the September 2026 backend revision. This is the canonical capability/status record; [remaining work and decisions](BACKEND_REVISION_REMAINING.md) are the completion checklist. Historical acceptance documents are evidence at their recorded revision, not proof of the current deployment.

## Status meanings

- `shipped`: implemented source with existing automated coverage; does not imply production activation or exhaustive provider acceptance.
- `staging-gated`: implemented or in the current implementation slice, but unavailable for production until its named acceptance gate passes. In-progress items are explicitly identified.
- `planned`: engineering work not yet implemented end to end.
- `deferred`: intentionally later program, often requiring a provider or business decision.
- `rejected`: not promised in this program.

## Trust boundaries

### Release evidence

Source `97b34c9` is pushed to `backend/resource-foundation`. Staging Worker version `ca7f4f43-a9e7-4eab-95d0-b91ac4be5dde` is deployed at [the existing staging site](https://wgp-catalog-staging.whittgoldsmithmedia.workers.dev). Final local gates: 343 tests/zero failures, typecheck/build pass, lint zero errors/six baseline warnings. Both browser harnesses passed; fixtures include owner library search → open photo → persisted cover, and cover authorization/CSRF/stale/foreign/hidden rejection.

Live readback: public galleries returned HTTP 200 with an empty bounded page (`limit=50`), `limit=51` returned structured HTTP 400, anonymous library returned 401, and legacy capabilities remained HTTP 200 with checkout unavailable. Signed-in owner library showed the three real private photos. No actual gallery cover was changed for acceptance; no photo was published. GitHub CI remains in progress, and the dependency advisory audit timed out again, so no clean advisory result is claimed.

- **Owner:** Better Auth identity must exactly match configured owner IDs on the server. UI visibility is not authorization. Owner edits still require schema validation, revisions and auditable state transitions.
- **Customer:** authenticated identity scopes proofs, quotes, orders and purchased grants. Browser prices, names, licenses, payment state and object keys are never authoritative.
- **Guest/anonymous:** can discover only permitted public galleries and view media allowed by current gallery/password policy. No guest proof/account impersonation or invite capability exists yet.
- **Stripe:** raw-body signatures and server-side provider/account readbacks bind events to saved orders. A redirect/success page cannot create entitlement. Webhook and customer delivery gates are independent; signing-secret configuration alone is not acceptance.
- **R2/Images:** originals stay in the explicit private catalog bucket; derivative access rechecks gallery/photo state. Watermark processing is distinct from authorization. Never expose original keys or transfer tokens in public JSON/logs.
- **Worker/database:** staging bindings and generated config must be verified, with explicit Worker name, empty resolved environment and preserved runtime variables. Runtime credentials are secrets, never committed configuration. PGlite tests do not establish independent-connection PostgreSQL contention behavior.
- **Legacy:** `src/lib/store.ts`, old `src/lib/shop-fns.ts` flows and browser-local catalog routes are non-authoritative. Disabled Settings/Keywords/Migrate/Publish/order UI does not mean every legacy server route has been deleted. Preserve history but review/retire legacy server reachability separately.

## Migration inventory

Routing implementation note: `src/routes/api/catalog_.$.ts` declares `/api/catalog_/$`. The trailing underscore is TanStack's non-nesting route marker, not part of the HTTP URL; the served catch-all remains `/api/catalog/$`. This keeps the legacy `/api/catalog` root from being intercepted.

The [100-gallery/10,000-photo baseline](BACKEND_SLOS.md) now runs real resource SQL with bounded payload/query-count checks. This is a local regression budget, not production SLO certification; CI artifact upload and independent staging latency measurements remain.

The [live Stripe readiness review](LIVE_STRIPE_READINESS.md) found an existing live account and three failed legacy webhook deliveries (HTTP 400 Invalid signature). No endpoint/secret/payment state was changed. Live integration is blocked on the documented implementation, reconciliation, policy and acceptance work—not configured for this new catalog.

Presence in this inventory does **not** mean a migration is applied to production.
